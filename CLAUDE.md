This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`atrgrid` — a daily (13:00 Taipei) advisory tool for Taiwan-listed ETF grid trading. Every trading day it computes, per holding, an ATR-sized grid step, compares live price to a stored "anchor," and outputs a BUY/SELL/HOLD/REVIEW/SKIP recommendation. It does **not** place orders — output is a suggestion the user executes manually and then feeds back via `atrgrid record`. See README.md for the full trading-logic writeup (lot sizing, anchor drift, ex-dividend handling, risk gates, per-asset-class parameters) — read it before changing `engine.py`, `fees.py`, or `config.py`, since the domain rules are non-obvious and largely documented there rather than in code comments.

CLI entry point is `atrgrid` (installed via `[project.scripts]`, backed by `src/atrgrid/cli.py:main`). Key subcommands: `init`, `advise`, `record`, `status`, `lot`, `verify-tickers`, `backtest`, `fetch`, `serve`, `export-page`.

Offline dev/testing (no network): synthetic bars live in `data/bars/` (generated by `scripts/make_demo_data.py`, **not real market data**):

```bash

atrgrid backtest 0052 00725B --provider csv --csv-dir data/bars
```

## Architecture

Two-file config, one persisted-state file, one pure-ish decision engine:

- `config/settings.yaml` — global params: fee discount/minimum, per-asset-class (`equity`/`bond`/`leveraged`) `GridParams` defaults, risk settings (`cash`, `cash_floor`, `max_data_staleness_days`, `min_step_cost_multiple`).
- `config/portfolio.yaml` — holdings list (ticker, Chinese name, class, shares, avg_cost, optional per-ticker `grid` overrides and `ex_dividends`). **A holding with `ticker_verified: false` produces zero recommendations** — this is a hard gate in `engine.evaluate`, not a warning. Tickers must be confirmed against exchange data via `atrgrid verify-tickers` before flipping this to `true`.
- `state/state.json` — the only mutable, persisted state: anchor price, rung count, cost-basis lots (for LIFO sell-basis calc), cash, trade history. `atrgrid advise` never writes this; only `atrgrid record` (real fills) or backtest runs (`--persist-anchors` in CI) do. This file is meant to be committed.

Module responsibilities (`src/atrgrid/`):
- `config.py` — loads/validates both YAML files into frozen dataclasses (`Settings`, `Portfolio`, `Holding`, `GridParams`). `resolve_params()` merges per-asset-class defaults with a holding's `grid:` override block.
- `fees.py` — Taiwan brokerage fee/tax math and the "one lot = max shares where fee still rounds to the minimum (NT$1)" sizing rule that drives everything else.
- `indicators.py` — Wilder ATR(14) and EMA, computed only from **closed** daily bars (today's incomplete bar is always excluded to avoid look-ahead).
- `engine.py` — the core decision function `evaluate()`: staleness/gap checks → ATR → grid step → rung distance from anchor → six risk gates (ticker unverified, stale data, gap > N×ATR, position rung limits, cash floor, no-loss-sell) → `Decision`. `commit()` applies an actually-filled trade to `State`. Anchor drift (`apply_anchor_drift`, EMA-following, `up_only` by default) and ex-dividend anchor correction (`apply_ex_dividends`) both mutate `Position` in place as a side effect of `evaluate()`, before the grid math runs.
- `state.py` — `Position`/`Trade`/`State` persistence, LIFO cost-basis tracking for realized P&L on sells.
- `data.py` — `PriceProvider` implementations: `YahooProvider`, `TwseProvider`, `FinMindProvider`, `CsvProvider` (offline), `ChainProvider` (tries them in order, first success wins; `auto` = Yahoo → TWSE → FinMind). `security_name()` is used by `verify-tickers`.
- `backtest.py`, `report.py`, `web.py` + `static/app.html`, `cli.py` — backtesting, text/markdown/HTML report rendering, the local-only (`127.0.0.1`, no auth) web console, and argument parsing respectively. The web console calls into the same `engine.evaluate`/`commit` — don't duplicate decision logic in `web.py` or `static/app.html`.

`.github/workflows/daily-advice.yml` runs `atrgrid advise --provider twse --persist-anchors` on a cron and commits `state/` back to the repo — state mutations from that job are expected, not drift to "fix."

### Known sharp edges

- `cmd_verify_tickers` (`cli.py`) compares the Chinese `name` in `portfolio.yaml` against the provider's registered name via substring containment. When the active provider returns an **English** name (e.g. Yahoo's `longName` for TW tickers), this comparison can never match, so it flags false-positive mismatches for essentially any Yahoo-backed lookup — a `!!` there is not on its own evidence the ticker is wrong; cross-check the actual fund identity before "fixing" a ticker based on this output alone.
- Data providers (`data.py`) hit live network endpoints (Yahoo/TWSE/FinMind) with no offline mocks beyond `tests/test_providers.py`'s recorded-response fixtures — the dev sandbox typically has no outbound network, so provider-parsing regressions from upstream field changes only surface when actually run against the live services.
